## L1 — Board cell edits are silently dropped when the column is missing
- Severity: bug
- Where: `hooks/core/board.ts:175`, `hooks/views.tsx:569`, `hooks/views.tsx:700`, `hooks/views.tsx:710`, `hooks/desk.tsx:1197`, `hooks/desk.tsx:1209`, `hooks/register.tsx:251`, `hooks/ai.ts:103`
- Abstraction: `setCells`/`editRow` say "set these cells of ticket N's row" over a typed Column map, so any column looks writable.
- Leak: `parseBoard` requires only the `#` and Status columns. `setCells` does `if (idx === undefined) continue`, with no error and no return value saying the cell was skipped. Callers have to know which header names this BOARD.md happens to have.
- Consequence: on a board with no Mode, Blocked by or Notes column, the pane says "Mode → solo" or "Dependencies saved" when nothing was written. A status move that carries a note moves the status and loses the note.
- Fix direction: `setCells` should report the cells it could not write, either by returning them or by throwing. The UI should hide or disable controls for columns the board does not have.
- Plan link: —
- Ticket: 0023

## L2 — The configurable tickets folder is honoured only by the pane
- Severity: bug
- Where: `hooks/core/query.ts:153`, `hooks/store.ts:210`, `hooks/register.tsx:22`, `hooks/ai.ts:52`, `skills/ticket/SKILL.md:23`, `agents/planner.md`, `.claude/agents/router.md:19`, `.claude/agents/worker.md:12`, `templates/BOARD.md:3`
- Abstraction: the plugin setting `ticketsDir` ("Folder … that holds BOARD.md and the ticket folders") makes the board location configurable, and the pane resolves every path through `dir()`/`boardPath()`.
- Leak: `ROUTER_TAIL`, which goes into every Run line, hard-codes "update tickets/BOARD.md". `runLine` takes no path. The ticket, planning, design and brainstorm skills, the planner, the router, the worker and the BOARD template all hard-code `tickets/`. The writer brief passes `dir()` and also tells the agent to follow `SKILL.md`, which says `tickets/`.
- Consequence: with any value other than `tickets`, the pane watches `<ticketsDir>/BOARD.md` while the Run button, the router, `/ticket` and replans read and update `tickets/BOARD.md`. The two boards drift apart with no warning.
- Fix direction: pass the resolved board path into `runLine` and every agent brief, and have the skills and agents say "the board path you were given (default `tickets/BOARD.md`)". Otherwise drop the setting.
- Plan link: — (PLAN.md:200 lists `ticketsDir` as a setting)
- Ticket: 0025

## L3 — "Resolved question" is defined only by a pane regex, and that regex is wrong
- Severity: bug
- Where: `hooks/core/ticket.ts:115`, `hooks/core/ticket.ts:146`, `skills/ticket/SKILL.md:121`, `.claude/agents/router.md:25`
- Abstraction: `Question.isResolved` says whether an open question has been answered, whether a person, the pane or an agent wrote the answer.
- Leak: the resolved markers are a shared convention (`**Resolved <date> (who): …**`, `~~`, `[x]`) that only this heuristic defines. `/\bresolved\b.*\(human|agent\)/i` parses as `resolved.*\(human` OR `agent\)`. The router reads "has open questions" in its own way.
- Consequence: any detail line that contains `agent)`, for example "(ask the agent)", marks an unanswered question resolved. `readiness()` then shows "No open questions" and offers Mark ready, while the router may refuse the ticket, or the reverse.
- Fix direction: write the resolved marker into the standard, which the router reads, and have one function implement exactly that marker. Group the alternation as `\((human|agent)`.
- Plan link: — (PLAN.md:33 documents the forms)
- Ticket: 0024

## L4 — A binding line with only one half turns off the default for the other half
- Severity: bug
- Where: `hooks/core/roadmap.ts:401`, `hooks/core/roadmap.ts:1534`, `hooks/ai.ts:764`, `hooks/ai.ts:794`, `hooks/store.ts:797`
- Abstraction: `bindFromBoard`/`parseBindingLine` say which design and plan files the board uses. Without a binding line they default to `design/DESIGN.md` and `design/PLAN.md`, and the doc says "either half may be missing".
- Leak: once a `Design:`/`Plan:` line exists, a missing half resolves to `undefined`, not to the default. Adopt writes a one-sided line when it produced only one draft. The skills only describe the defaults for the case where there is no binding line at all.
- Consequence: after a design-only adopt, `/ticket-board:planning` writes `design/PLAN.md` but the pane never binds it. The Plan tab stays dim and `addPlanTicket` throws "No PLAN.md is bound". A plan-only adopt hides a later DESIGN.md the same way.
- Fix direction: a missing half should fall back to its default path when that file exists, so the binding line only overrides what it names.
- Plan link: —
- Ticket: 0026

## L5 — `refresh(force)` returns stale data while another refresh is running
- Severity: bug
- Where: `hooks/store.ts:370`, `hooks/store.ts:432`, `hooks/register.tsx:195`, `hooks/register.tsx:240`, `hooks/store.ts:629`, `hooks/ai.ts:239`, `hooks/ai.ts:423`
- Abstraction: `refresh($, force)` reads like "re-read the tickets folder now". Callers await it and then read `S.snap`.
- Leak: `if (S.isRefreshing) return false` runs before `force` is checked, so a forced refresh is dropped while the 3 s poll, or the `bg(refresh)` fired by a Write, is in flight. No caller checks the return value.
- Consequence: when a writer agent finishes, `turn.complete` reads the placeholder rd.md and eval.md. It counts open questions from stale text, reports "missing Docs" that are present, and writes that wrong note into BOARD.md and a toast.
- Fix direction: a forced refresh should wait for the run in flight and then read again, for example by sharing a promise and queuing one more run. Callers should then always get a fresh snapshot.
- Plan link: —
- Ticket: 0027

## L6 — `createPlanTickets` decides failure from the banner's colour

## L7 — Watch buttons drop the host's `{deny}` reply
- Severity: bug
- Where: `hooks/desk.tsx:1126`, `hooks/views.tsx:647`, `hooks/desk.tsx:179`
- Abstraction: `$.ui.view({ agentId })` shows an agent's transcript. When the host refuses, the promise resolves with `{ deny }` instead of rejecting.
- Leak: only `openTranscript` handles the resolved deny and falls back to the activity log. Both Watch buttons call the API with only `.catch(() => undefined)`.

- Fix direction: route every "show this agent" action through `openTranscript`, so the deny convention is handled in one place.

## L8 — The rd.md head fields (`Type:`) are parsed three different ways
- Severity: bug
- Where: `hooks/core/query.ts:136`, `hooks/core/ticket.ts:49`, `hooks/desk.tsx:840`, `hooks/desk.tsx:859`
- Abstraction: `ticket.ts` `headLines`/`headField` own the head block, meaning the lines above the first `## `.
- Leak: `kindOf` and `setKind` scan the first 12 lines with their own regex. `docSections` in desk.tsx drops every line in the document that starts with `type:`.
- Consequence: a `type: module` line inside a section or code fence disappears from the desktop ticket view. In a long head, a `Type:` line below line 12 is ignored, so the ticket is classified from its title words even though Plan: and Design: on nearby lines are read.
- Fix direction: one head parser in core, which `kindOf`, `setKind` and `docSections` all use.

## L9 — The Blocked by cell format and the 4-digit number width are left to callers
- Severity: risk
- Where: `hooks/core/board.ts:87`, `hooks/core/board.ts:116`, `hooks/core/board.ts:203`, `hooks/desk.tsx:1208`, `hooks/views.tsx:709`, `hooks/views.tsx:881`, `hooks/views.tsx:478`, `hooks/views.tsx:606`, `hooks/desk.tsx:288`, `hooks/desk.tsx:1142`, `hooks/desk.tsx:1246`
- Abstraction: `BoardRow.blockedBy` is a list of normalised ticket numbers.
- Leak: writes go through `setCells` as raw strings, so each form rebuilds the encoding: `/\d{1,4}/g` + `padStart(4)`, and `—` for an empty list. Readers check for the `—` sentinel themselves. Rows accept 5-digit numbers, but this encoding allows only 4.
- Consequence: a format change has to be made in about 8 places. Ticket 10000 or above in a dependency splits into two wrong blockers.
- Fix direction: give the board module `setBlockedBy(numbers[])` and an empty-cell helper, so the UI deals only with lists.

## L10 — Automatic plating depends on Box conventions view code has to know
- Severity: risk
- Where: `hooks/glass.tsx:162`, `hooks/plan.tsx:379`, `hooks/desk.tsx:551`, `hooks/desk.tsx:395`
- Abstraction: `glassUI` says the app's controls get plates wherever the glass and app colours disagree, so views can use Button, Select and Input normally.
- Leak: `plated()` skips any Box that has a `width` prop (treated as a table cell) or a key starting with `plate-`, and it only plates Boxes whose direct children are controls. Views add wrapper Boxes to work around this.
- Consequence: putting `width` on a Box that directly holds controls silently removes its plate, and those buttons draw in the wrong colours, but only in the light-glass/dark-app combination (or the reverse).
- Fix direction: use an explicit marker (a Cell or Plate component) instead of guessing from `width`, or plate each control itself.
- Plan link: —
- Ticket: 0031

## L11 — Palette objects are changed in place, so colours must be read lazily

- Where: `hooks/glass.tsx:96`, `hooks/desk.tsx:60`, `hooks/desk.tsx:168`, `hooks/views.tsx:268`, `hooks/views.tsx:1261`
- Abstraction: `G`, `HUE` and `STATUS_HEX` look like constant palettes.
- Leak: `setScheme` changes them with `Object.assign`, so any value copied at load time keeps the old scheme. desk.tsx needs `get hex()` getters, and views.tsx keeps a module-level `glass` flag set as a side effect of drawing.

- Fix direction: pass the palette into drawing (`palette($)` or a parameter) instead of changing shared objects.

## L12 — Outcome badges and note ownership are parsed from free-text Notes
