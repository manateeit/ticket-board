## L1 — designfile and roadmap disagree on where a section's Open questions end
- Severity: bug
- Where: `hooks/core/designfile.ts:33`, `hooks/core/designfile.ts:10`, `hooks/core/designfile.ts:13`, `hooks/core/roadmap.ts:88`, `hooks/core/roadmap.ts:61`, `hooks/core/roadmap.ts:119`
- Abstraction: `answerDesignQuestion` answers one open question of a D section, the same question the pane shows.
- Leak: the extent of the questions block is decided in two places:
  - designfile stops at the next `###` heading;
  - roadmap reads everything from `### Open questions` to the end of the section.

  The D heading regex and the `[ ]`/`[x]` strip are also duplicated in both files.
- Consequence: when a `### Notes` (or any `###`) subsection follows Open questions, its bullets show and count as open questions, which blocks approval. Answering one of them always fails with "That question changed in DESIGN.md", so the section can never be cleared from the pane.
- Fix direction: one function that finds a D section's questions block, used by both the reader and the answer writer.
- Plan link: —
- Ticket: 0039

## L2 — addRow silently drops values for columns the board lacks
- Severity: bug
- Where: `hooks/core/board.ts:237`, `hooks/store.ts:815`, `hooks/views.tsx:903`
- Abstraction: `addRow(text, NewRow)` appends a typed row, as `setCells` does after 0023.
- Leak: `addRow` writes `''` for any column the board doesn't have and doesn't report what it dropped. The 0023 fix covered `setCells` but not this path.
- Consequence: on a board without Blocked by or Mode, a new ticket with dependencies loses them, and the pane still says "Created". The router can then run the ticket before its blockers are done.
- Fix direction: `addRow` should report skipped columns like `setCells` does, and the new-ticket form should say what wasn't saved or hide those fields.
- Plan link: — (follow-up to 0023)
- Ticket: 0036

## L3 — Adopt replaces the whole binding line, so a one-sided adopt unbinds the other half
- Severity: bug
- Where: `hooks/core/roadmap.ts:1545`, `hooks/ai.ts:796`, `hooks/core/roadmap.ts:400`
- Abstraction: `setBindingLine(board, design, plan)` reads as "bind these files". After 0026, a line overrides only the halves it names.
- Leak: `setBindingLine` rewrites the line with only the halves it was given, and `applyAdopt` passes `undefined` for the half the proposal lacks.
- Consequence: a board bound to `docs/arch.md` and `docs/roadmap.md` that adopts a plan-only proposal loses `docs/arch.md` without any warning. The design half falls back to a `design/DESIGN.md` that doesn't exist.
- Fix direction: `setBindingLine` should keep any half it isn't given.

## L4 — Replan Apply stamps the current design version, not the proposal's
- Severity: bug
- Where: `hooks/ai.ts:529`, `hooks/plan.tsx:1182`, `hooks/core/roadmap.ts:1222`
- Abstraction: Apply refuses to apply a proposal to a plan it wasn't made from.
- Leak: the safety check covers only the PLAN.md hash. Whether the design version is still current is checked only in the banner (`isCurrent`), and `applyReplan` writes the current design version rather than `proposal.designVersion`.
- Consequence: if review stays open across a redesign (v2 to v3), applying any item writes `design-version: 3`. The "plan is behind" signal clears even though v3 was never planned.
- Fix direction: Apply should stamp the proposal's own design version, or refuse when the proposal isn't current.
- Plan link: —
- Ticket: 0038

## L5 — Replan ticks are item positions that outlive a rewritten proposal
- Severity: bug
- Where: `hooks/plan.tsx:1225`, `hooks/store.ts:133`, `hooks/core/roadmap.ts:1058`, `hooks/ai.ts:380`
- Abstraction: `S.replanTicks` holds "the items the person ticked".
- Leak: ticks are stored as item indexes with nothing identifying which proposal they belong to. A new same-day replan overwrites `<date>-replan.md`, and `finishReplan` doesn't clear the ticks.
- Consequence: a person ticks items while the planner rewrites the file. Apply then applies whatever new items now sit at those positions, which can be Drops or Adds the person never chose.
- Fix direction: tie ticks to the proposal (path plus hash or item ids), and clear them when the proposal changes.
- Plan link: —
- Ticket: 0038

## L6 — The pane's own notes break its "AI " ownership prefix
- Severity: bug

## L10 — Markdown treats the palette map as the status list, prototype keys included
